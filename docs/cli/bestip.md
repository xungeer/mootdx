# `mootdx bestip`

## 用途

测试 Mootdx 内置的标准行情（HQ）、扩展行情（EX）和财务数据（GP）服务器，选择响应较快的地址，并更新本地配置。

该命令是通达信 TCP 服务器测速工具，不会启动 HTTP 服务。

## 参数

| 参数 | 默认值 | 说明 |
| --- | --- | --- |
| `-l, --limit INTEGER` | `5` | 表格中最多显示每类服务器的前几个结果。 |
| `-v, --verbose` | 关闭 | 输出逐个服务器的连接结果和排序表。该参数可重复，但当前 `-v` 与 `-vv` 没有不同的详细级别。 |
| `-h, --help` | — | 显示帮助。 |

当前命令没有 `--write`、`--tofile` 或只测速不写配置的选项。

## 示例

显示每类服务器响应最快的 3 个结果：

```shell
mootdx bestip --limit 3 --verbose
```

也可以通过模块入口执行：

```shell
python -m mootdx bestip -l 3 -v
```

测速结果取决于运行时网络环境，因此服务器地址和响应时间不会与固定示例完全相同。

## 配置写入

无论是否传入 `--verbose`，命令都会在测速结束后写入：

```text
~/.mootdx/config.json
```

配置包含 HQ、EX、GP 三类服务器的选择结果。请不要使用旧文档中的 `-w/--write`；当前版本始终执行写入。

## 边界与限制

- 命令需要访问多个外部 TCP 服务器，执行时间和结果受网络、防火墙及服务器状态影响。
- 不能通过 CLI 只测试 HQ、EX 或 GP 中的某一类服务器。
- `--limit` 只控制每类结果表和候选返回数量，不会减少前置的服务器连通性测试。
- 配置文件会被直接更新；如需保留现有配置，请在运行前自行备份。
- 在同一 Python 进程中反复调用底层异步测速接口存在模块状态依赖；命令行场景建议每次启动独立进程。
